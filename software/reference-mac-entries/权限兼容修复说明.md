# New Cam 1.0 安装权限兼容修复 · 2026-10-29

用户00:33报告：两个包和桌面图标已导入，boot主题启用成功；session-enable报newcam-session目录ownership/mode不可信，session rollback同错，boot随后已成功回退。报告没有给出目录实际uid/mode，不能说已直接测得Pi为0775。

源码显示session helper先检查路径，再用默认mkdir创建工作目录，接着要求全部祖先不可组写。保持此前已知祖先0755，umask0002可精确复现同路径错误：新目录0775、空mutation.lock0664，旧自启动文件未修改。先前Mac默认0022的测试漏掉此差异。

修复仅在Mac侧：调用冻结session helper前固定该进程umask0077；新增修复并继续安装入口。修复时现场验证冻结包manifest、父目录、用户所有权、0775目录、只含一个空且未占用的普通锁文件、旧启动链未切换，再记录原权限并收紧为0700/0600。不递归chmod，不改父目录，不删除文件，不替换已安装包；未知状态拒绝。修复后继续正常安装，成功后用户正常关机/开机观察。

24项本地测试通过，含宽松umask全流程、重复修复/启用/回退，以及未知文件/模式、符号链接、锁占用、包/父目录/启动项变化拒绝。1.0冻结包及全部发布源与归档仍一致。实际Pi修复待用户运行，本轮没有连接Pi。
